# TechFest Registration Website

A Django-based student registration website for a college techfest. It was built as a team project to support student registration, event selection, payment-step information, and an admit-card flow.

## What it demonstrates

- Django views, templates, forms, and models
- A multi-step student registration experience
- Responsive frontend work with HTML, CSS, JavaScript, and Bootstrap
- Team delivery under a college-event deadline

My contribution focused on the frontend and registration experience. This is a college project, not an actively operated production service. Do not assume that any old deployment or event data is still current.

## Run locally

Requirements: Python 3.11 recommended, pip, and Git.

```bash
git clone https://github.com/pandeynikhilone/TechFestEvent.git
cd TechFestEvent
python -m venv .venv
```

Activate the virtual environment:

- **Windows PowerShell:** `.venv\Scripts\Activate.ps1`
- **macOS/Linux:** `source .venv/bin/activate`

Install dependencies and create your local environment file:

```bash
python -m pip install -r requirements.txt
```

Copy `.env.example` to `.env` (PowerShell: `Copy-Item .env.example .env`) and replace the placeholder Django key with a long random local key. The `.env` file is ignored by Git.

Run migrations and start the development server:

```bash
python manage.py migrate
python manage.py runserver
```

Open [http://127.0.0.1:8000](http://127.0.0.1:8000).

## Configuration and security

The project reads configuration from environment variables or a local `.env` file:

| Variable | Purpose |
|---|---|
| `DJANGO_SECRET_KEY` | Required secret used by Django |
| `DJANGO_DEBUG` | Set to `True` only for local development |
| `DJANGO_ALLOWED_HOSTS` | Comma-separated host names allowed by Django |
| `RAZORPAY_KEY_ID` | Optional payment gateway key ID |
| `RAZORPAY_KEY_SECRET` | Optional payment gateway secret |

Use your own Razorpay test credentials if you exercise the payment flow. Never commit a real `.env` file or production credentials. Before any deployment, set a strong secret key, disable debug mode, configure the exact allowed hosts, and review Django's deployment checklist.

The local database is generated by migrations. Do not commit SQLite databases containing registrations or personal information.
